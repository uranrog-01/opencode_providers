How it works

Four steps from nothing to a model OpenCode can use.

These are the real app, captured against a demo config — no mockups. Every step writes into your opencode.jsonc, and nothing is saved until you press Save changes.

01 — Name it

Add a provider

Add provider asks for the provider id. That string becomes the key under "provider" in the config, so it is the one thing worth getting right up front.

02 — Point it somewhere

Fill in the URL and the key

Give it a display name, a baseURL and the API key. The API format is chosen from the usual SDKs, and an OpenAI-compatible relay is the default. The key is masked on screen, and a blank field never erases a key that is already saved.

  • name · baseURL · apiKey
  • blank field = leave the saved value alone

03 — Give it models

Add a model

Add models by ID and give them a display name. Context window and max output are looked up on models.dev as you type — each field is labelled auto or manual, and the moment you edit one it stops following recommendations.

  • context and output are written together, as the schema requires
  • Reset form hands a field back to the recommendation

04 — Save

One button, and it is live

Save changes writes the file: a .bak copy first, then 2-space JSON with your comments put back where they were. OpenCode picks it up on its next start, and the models you added are selectable.

Features

Built so it cannot lose your config.

The brief was “do not break the file”, and that shapes almost every decision in the editor.

Smart configuration

Display name, context window and max output are looked up on models.dev by model ID, Base URL host and API format — and refreshed on every save. A value you typed yourself is never overwritten.

Smart add

Reads the provider's own {baseURL}/models catalog, so a whole endpoint can be added at once instead of one row at a time. models.dev fills in whatever the provider left out.

Finds your setup

Checks PATH, npm, bun and pnpm global roots, scoop, chocolatey, winget, %LOCALAPPDATA%\Programs and C:\Program Files — then opens the global config for you.

Install

Download one file and run it.

No installer, and nothing to put beside it. Windows 10 (1903+) and Windows 11 already ship the runtime it needs. 

# grab the exe from the latest release, then double-click it
OpenCodeProvidersTool.exe

# or open a specific config instead of the global one
OpenCodeProvidersTool.exe C:\path\to\opencode.jsonc

Every save writes a .bak copy of the previous file first.

What it never touches

The edits stay in their lane.

Only the fields you actually change are written. Everything else — including keys this tool has never heard of — survives a save exactly as it was.

  • $schema, plugin, and every unedited provider
  • modalities, variants, cost, and an extra limit.input
  • comments in a .jsonc file, put back where they were
  • disabled_providers entries that belong to no provider block
  • an enabled_providers whitelist, kept in step with the toggle
